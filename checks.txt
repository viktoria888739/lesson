IntArray& operator=(const IntArray& other) {

Правильный ответ: 2) Если new бросит, объект сохранится; a = a здесь также безопасно.
Пояснение: Копирующий конструктор создаёт новый объект, а копирующее присваивание заменяет значение уже существующего. Здесь сначала делается поэлементная копия int в новый буфер и только потом delete[]: если new бросит, владение буфером сохранится, а a = a безопасно.

Вопрос 7/10. Перемещающее присваивание

1) Если this == &other, вернуть *this. Иначе освободить свой буфер, принять поля other, обнулить other и вернуть *this.
2) Скопировать поля other, оставив источник без изменений, чтобы оба объекта владели буфером.
3) Вызвать delete[] other.data, затем скопировать этот адрес в data.
Ваш ответ: Верно
Правильный ответ: 1) Если this == &other, вернуть *this. Иначе освободить свой буфер, принять поля other, обнулить other и вернуть *this.
Пояснение: При контракте «self-move сохраняет значение» совпадение this и &other нужно обработать отдельно и вернуть *this. Иначе старый буфер освобождают, владение принимают от other, а источник обнуляют, чтобы буфер не оказался у двух объектов.

Вопрос 10/10. Константная индексация
Есть две перегрузки ниже. a - обычный массив, c - const-массив, оба размера 3. Какое утверждение верно?

int& operator[](std::size_t i) { return data[i]; }
const int& operator[](std::size_t i) const { return data[i]; }

1) c[0] = 5 допустимо, потому что метод const.
2) a[0] = 5 и int x = c[0] допустимы; c[0] = 5 не компилируется.
3) a[10] = 5 обязательно бросит исключение.
Ваш ответ: Верно
Правильный ответ: 2) a[0] = 5 и int x = c[0] допустимы; c[0] = 5 не компилируется.
Пояснение: a[0] = 5 меняет элемент через неконстантный operator[], а int x = c[0] читает элемент через константную перегрузку; присваивание c[0] = 5 не компилируется, потому что она возвращает const int&. Выход за размер, например a[10], нарушает предусловие индексации и не обязан бросать исключение.
